Use only for an explicit orphan Entry candidate returned by governance. Legacy accepts a repository-relative path whose disk object no longer exists. Volumes v1 accepts code:<path> or a canonical database:// object identity and reproves the orphan from shared governance facts. Ordinary removal rejects any still-valid R reference. The sole exception is an exact machine ownership-conflict finding with different expected and actual owners and an existing expected formal owner; it removes only the misplaced Domain Entry while preserving that owner. The transaction guards Root, Meta, every declared object Volume, saved Evidence, and the existing Baseline/Database Binding. It removes no source file, database object, Evidence, Root, Meta, or Volume. Recovery, changed, unproven, or third-party state is rejected. Removing a non-orphan requires a maintainer decision recorded with aoci_report; never delete a workspace or database object merely to manufacture an orphan.
