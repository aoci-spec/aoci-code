AOCI-CODE MCP Runtime Contract v1
=================================

Transport and identity
----------------------

`aoci mcp` runs an MCP server over stdio. `serverInfo.name` is `aoci-code` and
`serverInfo.version` is the version injected into the running binary. Stdout is
reserved for JSON-RPC frames. Logs and diagnostics are written to stderr.

The current MCP protocol identity is `2025-11-25`.

Tool surface
------------

The public server exposes exactly these nine tools:

  aoci_get_entries
  aoci_header
  aoci_maintain
  aoci_overview
  aoci_remove_entry
  aoci_report
  aoci_rules
  aoci_search
  aoci_update_entry

The SHA-256 identity of the sorted names, joined by LF with a final LF, is:

  b4a56cb6d4e625189708e2132a45094eecc62a05c6a1bd4d06ddd0471598176e

Schemas and behavior
--------------------

The tool descriptions and input schemas returned by the running server are the
machine contract. Tools resolve the repository passed to the server and load
current repository state for each call. A protocol error is returned as an MCP
error result; it is not printed as a second stdout message.

Descriptions say what a tool does, when to call it, and what it may write; the
session contract (`aoci_rules`), the Guide, and each response's own fields carry
the procedure, so a description does not repeat them. Every call is validated
against the closed input schema its tool registered. `tools/list` shows that
schema except for two `aoci_overview` members a Host never composes from
scratch: `cognition_receipt`, which passes back a receipt a previous response
returned, and `probe_answers`, which answers the probe `check_only` just issued.
They are listed as plain objects and keep their closed shapes for validation,
so a call that breaks either shape is refused exactly as before.

The nine-tool identity is independent from optional CLI lifecycle commands.
Changing a CLI command does not implicitly add, remove, or rename an MCP tool.

Layout acceptance
-----------------

Every tool reads both layouts. On a Volumes v1 repository the write tools
(`aoci_maintain`, `aoci_update_entry`, `aoci_remove_entry`) follow the
Cognition Volumes contract and `aoci_report` answers `volume_read_only`. On a
Legacy single-file layout no tool writes since 0.2.0: `aoci_maintain` answers
`status=stopped` with one finding whose cause starts with
`legacy_read_only_migrate_required`, `next_action=migrate_legacy_repository`,
and `next_commands` carrying `cognition onboard start --json` and the Guide;
`aoci_update_entry`, `aoci_remove_entry`, and `aoci_report` return the error
code `legacy_read_only_migrate_required`. `aoci_overview`, `aoci_get_entries`,
`aoci_search`, `aoci_header`, and `aoci_rules` keep their Legacy read
behavior. No tool is added, removed, or renamed by this rule.
