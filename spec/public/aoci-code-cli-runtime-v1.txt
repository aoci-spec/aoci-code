AOCI-CODE CLI Runtime Contract v1
=================================

Identity
--------

The installed binary is named `aoci`. The canonical Go module is
`github.com/aoci-spec/aoci-code`. The command tree and the exact flags exposed
by the current binary are discoverable through `aoci --help` and command-level
`--help` output.

Global behavior
---------------

`--repo` binds an invocation to a repository root. `--json` selects the
machine-readable output for commands that support it. `--quiet` suppresses
eligible human progress output; it does not change the result or authorization
boundary.

The stable process exit classes are:

  0 success
  1 drift or ordinary check failure
  2 invalid input, index, or governance state
  3 uninitialized repository, configuration, or parameter failure
  10 internal failure

One `--json` invocation emits at most one top-level business result or error
envelope. Human-readable errors are written to stderr. The `aoci mcp` command
uses a direct stdio protocol path described by the MCP runtime contract.

`status` distinguishes a missing Baseline from an unreadable or invalid one.
A missing Baseline remains a successful status result with
baseline_exists=false; a Baseline read or decode failure exits 2 and uses the
existing error envelope under `--json`, rather than reporting it as missing.

`aoci ui` serves a local, read-only status page for one or more repositories:
identity, index header, Code and Database Volumes, budget, the Overview chunk
plan at the configured chunk_tokens, governance drift, host integrations, the
running `aoci mcp` processes of the current user (Linux), and the next step the
Guide recommends. It binds loopback addresses only and refuses any other bind
address, answers GET and HEAD only, takes no lock, appends nothing to the
Ledger, and is not an MCP transport: the `aoci mcp` process never opens a
socket, and the nine-tool surface is unchanged. The page's JSON routes are an
implementation detail of the same binary, not a public contract; Hosts keep
reading `capabilities` and the Guide.
`aoci ui --detach` starts the page as its own session, detached from the
calling shell, prints its URL once the page is listening, and returns; a page
already registered and answering for the repository is reused when this
version started it; a tokenless page from an older binary is refused, by
`--detach` and by a foreground start alike, until `aoci ui --stop` ends it. `aoci ui --stop` ends the registered page, proving liveness through
the page itself before any signal is sent. Registrations live in the user's
cache directory (or AOCI_UI_REGISTRY_DIR), never in the repository.

The readiness URL contains a per-process access capability in its fragment.
The static page shell is public on loopback; repository lists, state, entries,
and raw assets require that capability in the Authorization header, including
HEAD and conditional requests. The browser retains it only in tab session
storage, removes the fragment when storage succeeds, and sends no credential
in request URLs. Treat the printed link and private registration as credentials.
Registrations retain their existing JSON shape and use owner-only file modes.
Legacy tokenless registrations remain readable for --stop, but a new --detach
refuses to reuse or replace a live legacy registration until --stop completes.
Older binaries cannot authenticate new pages; stop pages
with the binary that started them before a downgrade. MCP schemas and formal
cognition formats are unchanged.

State and writes
----------------

The binary ships no model endpoint client. Repository semantics are written
only by the Host model through the governed MCP write tools or `update-entry`;
the `ai` configuration block is read for compatibility and consumed by nothing.

A Legacy single-file layout (`aoci.txt` carrying its own Header and Entries,
no Root manifest) is read-only since 0.2.0. Its authoring commands are
retired: `ai`, `index build`, `index update`, `index entries`, `index header
draft`, `index header diff`, `index header apply`, `index agent plan`, `index
agent stage`, `index agent header`, `index agent curation`, and `doctor
--net`. `update-entry` and `remove-entry` on that layout exit with
`legacy_read_only_migrate_required` and write nothing; `index agent guide`
returns a blocked guide whose stage is that token and whose commands carry
`cognition onboard start --json`; `init --locale` and `config set locale`
refuse to change the Locale a Legacy index was written in. Reads (`verify`,
`check`, `status --deep`, `index score`, `index inventory`, `index header
show`, `scope status`, `capabilities`) and the Legacy-to-Volumes migration
(`cognition onboard`, `cognition bootstrap`, `cognition migration`) keep
their contracts. The Managed Scope transaction is the one path that still
edits a Legacy index document: a disposition retires an Entry, and a stale
Index source still needs its source-bound Entry candidate there.

Backups written beside host configuration and formal assets are published
with owner-only file permissions. On Windows, directory ACLs remain the
operating-system access boundary.

Command help and the live Guide identify whether an operation is observational,
prepares a candidate, requires human interaction, or can update formal assets.
An observational command does not modify the formal index or Baseline unless
its contract explicitly says otherwise, but local audit evidence can still be
written when enabled. Formal writes use the existing validation, lock, CAS,
atomic-write, and recovery pipeline.

Configuration commands
----------------------

`aoci config list`, `aoci config get <key>`, and `aoci config set <key> <value>`
read and write team configuration through the loader the configuration runtime
contract describes. `list` and `get` read the effective configuration, the team
file merged with eligible local overrides; `set` writes the team file only, so
a local override never leaks into it.
`exclude_root_dirs` is a comma-separated directory list that matches at the
repository root and wherever Git ignores a directory of that name; like
`exclude_dirs`, changing it after the first scan requires Scope Change. Both
lists take directory names: `set` drops a trailing separator and duplicates
and refuses a value containing a path separator, which could never match.

Under `--json`, `list` emits the effective configuration object, `get` emits
the key's value as a typed JSON value (string, boolean, integer, or array,
never prose), and `set` emits one result object:

  ok: true
  key: the key that was set
  value: the effective value after the write, exactly what the next
    `config get <key>` returns, so a local override of the same key shows
    here as it will show there
  restart_mcp_required: true, present only when the key is `locale`, because
    a running `aoci mcp` keeps its startup locale
  locale_migration: present only when a `locale` set leaves a migration
    pending: `header_pending` (boolean), `entry_paths` and `curation_paths`
    (counts), the same numbers human output prints

On a Legacy single-file index, `set locale` to a Locale other than the one
the index was written in exits 3 before any write: that index is read-only
until it migrates to Volumes v1.

The accepted keys are the ones the unknown-key message lists. An unknown key
or an invalid value exits 3 with the ordinary version-1 error envelope before
any write. Human output of these commands is not changed by this contract.

Managed Scope activation
------------------------

`aoci scope activate` activates the current desired scope and budget policy by
building an empty `managed-scope-candidate-set/v1` through the existing Scope
Change preview and Apply pipeline. It accepts no positional arguments or
command-specific flags, edits no rules, and authors no Entries. It preserves
the existing authorization, validation, lock, CAS, and recovery decisions.
When the desired policy, budget, and authorization posture already equal the
active Baseline receipt and the Plan moves no object, Entry, or fingerprint,
activation reports `already_aligned` with exit status 0, starts no formal
write, and records no transaction. `scope status` and `scope show` carry
`repository_root`, the root the reading was taken from.
In particular, a Legacy stale source still requires an explicit Entry candidate,
the one Legacy index write this release retains; Volumes source drift remains
available to subsequent ordinary maintenance.

When the preview does not require human interaction, activation attempts Apply.
Success exits 0 and `--json` emits the existing `managed-scope-change-result/v2`
object, with no additional envelope. Other failures retain the existing Scope
Change error behavior, including refusal when automation is off.

When the preview reports `interaction_required`, activation does not prompt or
attempt Apply. It saves the existing versioned preview in a unique directory
under `.aoci/scope-change/`, without replacing an earlier pending preview, and
exits 2. Human output names the preview and the approve and apply commands in
order. `--json` emits the ordinary version-1 error envelope with `ok=false`,
`exit_code=2`, `error_code=managed_scope_human_approval_required`, and these
required `details` fields:

  interaction_required: true
  formal_writes_started: false
  preview_file: absolute path to the saved preview
  approve_command: shell-quoted command bound to this executable and repository
  apply_command: shell-quoted command using the same preview and approval file

When the team's `human_approval_channel` admits the host dialog and the plan is
eligible for it, `details` also carries `host_dialog_request`: `tool` is
`aoci_maintain` and `arguments` are `intent=human_approval` with an
`approval_request` naming `kind=scope_change` and the repository-relative
`preview_file`. A host that shows MCP dialogs makes that call and the person
answers there; the approval it records lands where `apply_command` reads it.

The commands use `scope approve --actor <id> --out-file` followed by
`scope apply --approval-file`; the operator replaces the quoted <id> placeholder
with their reviewer identity. Approve retains its real-TTY digest confirmation;
its prompt says that Enter rejects, and a rejection prints what to do next.
`cognition migration approve` and `cognition bootstrap approve` take the same
`--out-file`.
Saving the preview is a runtime artifact write, not a formal cognition or
Baseline write. Apply still refuses changed sources or other stale guards and
never treats the saved preview alone as approval.

Bounded standard input
----------------------

Every command that reads standard input reads it under an explicit byte bound
and never buffers an unbounded stream. update-entry accepts at most the Entries
request limit and refuses a larger payload as a configuration error before any
formal write; supplying both --entry and --stdin is refused the same way, since
silently preferring one would write content the operator did not intend. Hook
runtime input carries a small private bound and fails open on a read error or an
oversize payload, because hook infrastructure must never block a workflow.

Hook configuration failures
---------------------------

Hook locale selection reads configuration without materializing a legacy Locale
migration. If configuration cannot be loaded, hooks use the default Locale:
pretool remains silent and exits 0 on that configuration failure, while
codex-compact still emits its refresh context and fresh refresh_event_id.
Ordinary commands continue to report configuration failures as exit 3. Existing
Recovery gates and strict pretool blocking for actual stale Entries are unchanged.

Layout-scoped read commands
---------------------------

Read-only commands this contract declares Legacy-only, including status --deep,
diagnose a Volumes v1 layout instead of reporting a result their governance path
owns.

The Legacy layout itself is read-only since 0.2.0 (see State and writes): the
retired authoring commands are absent from the command tree, and every
remaining write entry point answers legacy_read_only_migrate_required there.

Compatibility
-------------

Automation must consume JSON fields, schema versions, exit classes, and live
capability output instead of parsing human prose. A public contract change that
alters these surfaces requires matching compatibility tests.
