# 官方 Locale 稳定合同权威边界

本文只划分事实来源和冲突处理，不复制机器词表、数值、状态表或完整流程。稳定合同的具体内容仍位于下表所列来源。

| 层 | 权威范围 | 不得承担的范围 |
| --- | --- | --- |
| 当前源码、配置与测试 | 当前编译版本的实现、接口、字段和运行事实 | 不得静默偏离已发布 Spec；发现偏离应作为兼容缺陷处理 |
| `spec/` | 对外格式、JSON、状态语义和兼容边界 | 不保存可由机器直接消费的词表副本，不代替当前运行状态 |
| `internal/machinecontract` | Validator、扫描器和协议代码共同消费的机器数值、词表与集合 | 不承载长篇说明、入口教程或实验结论 |
| Validator 与确定性状态机 | Apply、Warning、退出码、状态迁移和安全拒绝的机器裁决 | 不生成 F/R/A/S、Header 或 Curation 业务语义 |
| `textassets` 清单登记的 `en-US` 与 `zh-CN` 资源 | 当前生产 Prompt、宿主合同、MCP Description、Guide 文案和仓库模板正文；两种官方 Locale 必须保持同构资产集合、变量和机器 token | 清单说明、Golden、另一 Locale 或历史副本不得成为运行时回退源 |
| Prompt | 告诉模型如何基于当前证据生成语义候选 | 不扩大机器能力，不覆盖 Validator、Spec、权限或安全裁决 |
| Guide 实时输出 | 针对当前 Plan、模式和仓库状态的下一步、命令顺序与安全停点 | 历史 Guide 和静态文档不得替代当前输出；Guide 文案不另设机器判据 |
| MCP Description 与 CLI Help | 工具用途、输入边界、副作用和入口选择 | 不重建完整状态机，不覆盖真实 Input Schema、结果 JSON 或当前 Guide |
| `aoci_rules` 的 runtime-rules | 当前会话的认知建立、复用、沟通和维护总合同 | 不复制专项阶段手册；具体阶段只按当前 Guide、工具 Schema 和 Help 执行 |
| `AGENTS.md` | 仓库接入、开发纪律和启动/收尾提示 | 不固定某次运行状态，不复制机器词表或专项状态机 |
| README 与 `docs/` | 面向人和宿主集成者的解释、示例与操作背景 | 不作为生产加载源；与 Spec、机器合同或当前输出冲突时不能单独裁决 |
| `testdata/golden` | 生产输出或摘要的派生兼容探测器 | 不被生产代码读取，不是正文事实源 |
| 私有归档（不在公开树中） | 绑定内部历史、模型或环境的非规范证据 | 不得进入生产嵌入、清单、Prompt、Spec 或兼容 Golden |

## 冲突处理

1. 当前实现事实与已发布 Spec 不一致时，视为缺陷并停止把任一侧静默解释为“新标准”；按兼容变更流程修复并同步测试。
2. 静态说明与当前 Guide、真实 Schema 或 Validator 结果不一致时，以当前机器结果定位问题，修正文档或资源，不修改机器结果去迎合旧副本。
3. 任一生产 Locale 资源缺失、重复、损坏、变量不一致或清单不一致时必须显式失败，不得回退到另一 Locale、Go 字符串、Golden、实验 Prompt 或历史文档。
4. 机器词表、数值或集合需要变化时，只修改 `internal/machinecontract` 的对应权威并更新语义说明与等价测试；Shell、Spec、Prompt 和测试不得重新保存完整机器集合。
5. 文案与行为的兼容快照必须绑定真实生产装配结果。直接资源和长 Prompt 优先保存 SHA-256；只有多资源装配输出或完整协议结构才保留全文 Golden。
