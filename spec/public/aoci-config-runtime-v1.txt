AOCI-CODE Configuration Runtime Contract v1
===========================================

Files and precedence
--------------------

Team configuration is stored in `.aoci/config.json`. Local configuration is
stored in `.aoci/config.local.json` and is not intended for version control.
Runtime loading applies safe defaults, then the team file, then eligible local
overrides. Team-owned governance fields cannot be changed by the local layer.

The configured `index_path` selects the cognition root. `locale` selects one
official Locale for generated assets and process output. Inventory exclusions,
curation exclusions, line-ending policy, cognition refresh threshold, Overview
delivery framing, managed scope, cognition budget, automation, Database Source
declarations, authoring batch sizes and the Maintain transport budget
(`code_cognition_batch_entries`, `maintain_transport_budget_bytes`,
`database_cognition_batch_objects`, `database_cognition_batch_evidence_bytes`),
and installed Host integrations are team-owned settings. A batch size is a
shared authoring contract between the machine and every Host that maintains
the repository, so the local layer cannot change it.

`exclude_root_dirs` is a team-owned directory exclusion list that matches
at the repository root and wherever Git ignores a directory of that name.
New `init` persists ambiguous artifact names there; an absent list retains
the old any-depth `exclude_dirs` behavior and policy identity. Changing either
list after the first scan requires a governed Scope Change. Both lists hold
directory names, never paths: `config set` drops a trailing separator and
duplicates and refuses a value containing a path separator.

`sensitive_name_rules` is a team-owned selector for the built-in
sensitive-name rule set of Safe Inventory, `v1` or `v2` as the Safe Inventory
contract defines them. New `init` persists `v2`; an absent key is `v1` and
retains the old rules identity. The local layer cannot change it, `config
set` refuses any other value, and changing it after the first scan requires
a governed Scope Change.

`code_cognition_parallel_batches` is a team-owned integer defined by the
Cognition Volumes contract for parallel current batches (implemented in
0.2.0-rc2): absent or 1 keeps one current batch per Maintain, the wire
ceiling is 4, the local layer cannot change it, and it enters no policy,
scope, or authorization identity. A binary that predates the implementation
treats the key as unknown, exactly as it treats any key it does not define.

`human_approval_channel` is a team-owned choice of how a protected change may
reach its person: `tty_or_host_dialog` (absent, the default) admits the
terminal phrase and the MCP host's dialog, and `tty_only` admits the terminal
alone. The local layer cannot change it and `config set` refuses any other
value. Apply judges it when a transaction starts. It enters no policy, scope,
or authorization identity, so changing it is not a Scope Change.

Secrets and network configuration
---------------------------------

The `ai` block is accepted for compatibility with files written before 0.2.0
and consumed by nothing: the binary ships no model endpoint client. Its
`api_key_env` was always an environment-variable name, not a credential value.
Database Source configuration stores the credential environment-variable name
rather than the credential. Secret values must not be persisted in
configuration, formal cognition, or Ledger records.

Compatibility and validation
----------------------------

The current `internal/config` decoder and validator are the executable field,
default, merge, and error authority. Callers that write team configuration must
start from the team layer rather than writing a local merged view back to disk.
Unknown or invalid policy values fail according to the command using them; they
do not silently weaken a safety boundary.
